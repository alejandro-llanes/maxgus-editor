maxgus

Lightning fast, and drawn by the GPU. An Emacs written in Rust: ligatures, blur behind every popup, a cursor that travels rather than appears, documentation set in prose beside your code, tree-sitter, a language server, magit — and the same editor in a terminal, over ssh.

$ curl -fsSL https://alejandrollanes.com/maxgus-editor/install.sh | sh -s -- --build gui

That is the window, and it goes in the application menu. Leave -s -- --build gui off for full, the same editor for a terminal only; --build minimal is the one with nothing to install. Each writes a configuration and the themes the first time, and never over your own.

How fast

Fast is not a slogan here; it is what every part was built to be, and what it says about itself when it starts.

5 ms

to a file on the screen

From the shell handing over to a 5,000-line Rust file drawn, parsed and coloured by tree-sitter, in a terminal. The editor's own clock — M-x startup-time, the way emacs-init-time does it — reads under a millisecond.

0 ms

spent waiting on anything

Every file read, directory walk, subprocess and language-server call runs on tokio. A command is a plain function that queues work and returns, so nothing ever holds the keyboard — and a test fails the build on a blocking call anywhere off the startup path.

1 frame

when something changes, none when it does not

The window is wgpu: glyphs, panels and blur in a few passes over the GPU. It sleeps while nothing is happening rather than redrawing a still screen sixty times a second, and a keystroke wakes it.

1 keypress

is what zoom costs

C-x C-+ re-cuts the font from what is already in memory and lays the grid out for the cells that now fit. Nothing is looked up on the system and nothing is reloaded; the text is larger before the key is up.

3 passes

for the blur, and only while a popup is open

A popup sits on a blurred copy of what it covers: the frame behind, one pass across, one down, and the result shown only inside the popup's rectangle. With none open the frame is drawn once and the blur costs nothing at all.

0 interpreters

between you and the editor

No Lisp and no plugin runtime. Configuration is a declarative file read once; a Rhai script, if you write one, adds commands and is on the path of no key you did not bind to it. The editor is one binary that is ready when it is on the screen.

Three builds

The same editor with different parts left out. Every binary's --version says which one it is, and a key a build does not have reports itself as undefined rather than doing nothing. The whole table lists every feature against every build.

On your machine

Every release carries all three builds for Linux, macOS, Windows and FreeBSD, each with a .sha256 beside it. The install line above works out which archive your machine wants; below is the same thing said per platform, and the archives are there if you would rather not pipe anything into a shell.

Linux

glibc, musl and aarch64. A musl system gets the static build, which runs anywhere; the script works that out from ldd.

$ curl -fsSL …/install.sh | sh \
    -s -- --build gui
# or the terminal-only build:
$ curl -fsSL …/install.sh | sh
  • x86_64 — all three builds
  • x86_64 static (musl) — no gui
  • aarch64 — no gui

macOS

Intel and Apple Silicon, all three builds. The same line: the script reads uname and takes the right archive.

$ curl -fsSL …/install.sh | sh \
    -s -- --build gui
  • Goes to ~/.local/bin unless --prefix says otherwise
  • Gatekeeper: the binary is not notarised, so the first run may need Open anyway in Privacy & Security

Windows

All three builds, as a .zip. There is no shell script for it — unzip it and put maxgus.exe somewhere on your PATH.

> set V=maxgus-gui-windows-x86_64
> curl.exe -LO …/%V%.zip
> tar -xf %V%.zip
  • Windows Terminal or any VT-capable console
  • C-z reports there is nothing to suspend into; the rest is the same editor

FreeBSD

minimal and full for x86_64. No gui: the release has no window system to compile it against.

$ curl -fsSL …/install.sh | sh
  • Needs curl or fetch

An archive, by hand

No script, no pipe. Every asset has a checksum beside it, and nothing here needs installing anywhere in particular.

$ f=maxgus-full-linux-x86_64.tar.gz
$ curl -fsSLO …/download/$f
$ curl -fsSLO …/download/$f.sha256
$ sha256sum -c $f.sha256
$ tar xzf $f

From source

Rust stable, edition 2024. minimal and full need nothing but a terminal; gui needs a window system's headers.

$ git clone …/maxgus-editor
$ cd maxgus-editor
$ cargo build --release   # full
$ cargo build --release \
    --features gui      # gui
  • Debian and relatives: libwayland-dev, libxkbcommon-dev

What it looks like

Not mock-ups. Every one of these is the editor's own redisplay — the window pictures are photographs of it running on a GPU, and the two terminal pictures at the end are drawn by the same draw a session runs.

In the window

The gui build is the same editor — the same commands, the same keys, the same redisplay — drawn into a window by wgpu rather than into a terminal by escape sequences. This is what the GPU buys.

Documentation set in prose new

C-c c k asks what the thing at point is, and the answer comes on a card beside the line rather than in a box of cells: the prose in a proportional face, wrapped at the pixel; the code in the editor's own font on a chip; rounded corners, a border, and a blur of what is behind it.

Blur behind every popup

The completion list, the doc box, the which-key panel: each sits on a blurred copy of what it covers rather than on a hole cut in the text. While no popup is open it costs nothing at all.

Ligatures, and a cursor that respects them

!= drawn as the one mark its font's designer drew, and ->, =>, <= with it. The text is shaped, so which characters join is the font's answer; they form only in code, and the cursor's own cell comes apart so a block over half of ≠ never hides what is under it.

A cursor that travels

The block slides to where point went and smears on the way — the corners at the back are given less of the distance — so the eye follows it across a jump rather than hunting for it. A hop of a cell gets its own, shorter timing. Six effects for it to leave behind, off unless asked: sonicboom, ripple, wireframe, railgun, torpedo, pixiedust.

Scrolling on a spring

Sub-line, driven by a critically damped spring rather than an easing curve, so a second wheel notch adds to the first instead of restarting it. Only the window being scrolled moves; the view a command moves — C-v, a search — slides too.

A wave under an error new

A diagnostic's underline is the wavy one, drawn by the GPU in the severity's colour, joined across the cells it runs under and as smooth at any zoom. undercurl=#true puts one under any face.

Zoom new

C-x C-+ and C-x C-- draw the text a tenth larger or smaller, C-x C-0 puts it back, and the wheel with control held does the same. The font is re-cut from what is already loaded, so it is as quick as a keypress should be.

A mark at the edge while it moves new

A thin bar at the right says where the window is in its buffer and how much of it it shows, the way a phone's does. It appears when the window scrolls and fades a moment after it stops, so a page being read has nothing at its edge.

Pictures new

A PNG, JPEG, GIF, WebP or BMP opens as a picture rather than as the bytes it is made of, at its own size where there is room. In a document, C-c o i opens the image a markdown or HTML line refers to, beside it.

Any font, sharp on any display

set gui-font names any family on the system. Bold and italic are their own faces where the family has them; a character it lacks — an ideograph, an emoji, in colour — comes from a font that has it. A display that reports a scale gets glyphs cut that much larger, and dragging the window to another one cuts them again.

A window that behaves like one new

Its title says the file, the project and a • while there is unsaved work. The close button refuses to throw that work away. It opens at the size it was last closed at, F11 fills the screen and gives it back, and it sleeps when nothing is happening.

The mouse, and the clipboard

Click to place point, drag to select, twice for the word, three times for the line, middle button to paste, a file dropped on the window to open it. The system clipboard rather than a terminal's guess at one, and the primary selection where there is one.

And in both

Everything below is in the window and in the terminal alike: one editor, one command set, one configuration.

Emacs keys, and Doom's

The classic bindings, and Doom's leader scheme under C-c. Prefix arguments, keyboard macros, registers, rectangles, the mark ring — and they behave like Emacs, down to how undo groups a run of typing.

which-key

Pause mid-sequence and a panel says what can follow it, so the leader is learned rather than memorised.

tree-sitter highlighting

Eleven grammars built in, re-parsed incrementally as you type — and any other language coloured by a grammar the system already has, or one the editor fetches and builds for you.

Grammars it installs itself

M-x install-grammar lists the five hundred parsers tree-sitter's wiki names, then clones, builds and loads the one you pick. Open a file in a language it has no grammar for and it offers, naming the repository it would clone. Nothing is fetched or built until you answer.

A language-server client

Diagnostics, go to definition, references, rename, code actions, formatting, completion — and a doc box beside the cursor, the way lsp-ui-doc does it.

Autocomplete

After a couple of letters, a list at the cursor of what the language server says could follow. Typing narrows it; RET takes one; every other key goes into the buffer.

magit

Status, staging by hunk, commits, branches, stashes, log, blame, and the transient menus they hang off.

A file tree

treemacs' keys, git status in the margin, and a side panel that stacks the tree, the symbol outline and the buffer list.

A terminal panel

A real pseudo-terminal along the bottom, in tabs, running whatever $SHELL says.

Project search, and editing the results

grep the project, then edit the matches in place and write them all back — wgrep.

Many cursors, and an undo tree

Take the next occurrence, and the next, and type once into all of them. Undo keeps what you undid: the history is a tree, with a visualiser.

Lines that wrap, when you ask

truncate-lines off wraps a long line across the rows below it rather than clipping it at the edge, and everything that counts lines counts rows with it.

beacon terminal

A light where the cursor lands after a jump — the terminal's answer to the question the window answers by moving the cursor there.

No Lisp interpreter

Configuration is a small declarative file. Scripting, where you want it, is Rhai. One binary, no runtime to install.

Configured in one file

~/.config/maxgus/config.kdl. Every node is optional, anything left out keeps its default, and a node it does not recognise is reported with a line number and skipped — so a file written for a newer version still starts an older one. 

// ---- settings ----
set theme="maxgus-dark"
set line-numbers=#true
set scroll-margin=3
set which-key=#true
set lsp-doc=#true
set beacon=#true

// ---- keys ----
keymap "global" {
    bind "C-c f" "lsp-format-buffer"
    unbind "C-z"
}
// ---- faces ----
theme "maxgus-dark" {
    face "font-lock-comment" fg="#5f6b73" italic=#true
    face "region" bg="#3a4048"
}

// ---- language servers ----
lsp "rust" command="rust-analyzer" {
    root-markers "Cargo.toml"
}

Getting going

Open a file and press C-h t for a guided tour, or C-h b to list every binding. C-x C-c leaves.

If C-c is a prefix you do not know yet, hold it: the panel will tell you what is under it.

The README is the long version; the reference lists every setting, face and key.

$ maxgus src/main.rs         # a window
$ maxgus -nw src/main.rs     # the terminal, spelled the way Emacs spells it
$ maxgus --version
maxgus 1.3.1 (gui)

# Install somewhere else, or an older release:
$ curl -fsSL …/install.sh | sh -s -- \
    --prefix /usr/local/bin --version v0.1.0
